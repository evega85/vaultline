# Vaultline: notes for contributors and coding agents

How to run, test and build is in README.md.

Design rules to keep:
- The database must stay readable by KeePassXC and KeePassium. TOTP is written only to the `otp` field as an otpauth URI. Legacy OTP fields are read but never rewritten unless the user changes the secret.
- All writes go through `Vault.save`: re-read the disk, merge if it changed, verify by decrypting again, back up locally, then write a temp file and use `os.replace`. Never write the .kdbx any other way. pykeepass's own `save(path)` falls back to copying over the file in place on Windows.
- New databases are made only by `vault.create_vault`: pykeepass's blank KDBX 4 template (AES-256, Argon2d) with a fresh root-folder UUID, checked by decrypting it, then renamed into place. It never overwrites an existing file.
- pykeepass work runs only on the controller's single worker thread. The UI uses `EntryView` snapshots.
- pyotp's 112-bit minimum secret length is turned off in `otp.py` on purpose, because real sites issue 80-bit secrets.
- Custom icons are written by hand into `Meta/CustomIcons` (UUID + Data only, valid in KDBX 4.0 and 4.1) with `CustomIconUUID` on the entry, because pykeepass has no API for them. Identical icons are shared, and unused ones are removed.
- Favicons are fetched directly from each site, never through a third-party icon service. Local or private hosts are skipped.
- Custom fields: anything `is_internal_field` reports (standard, OTP, KeePassXC-Browser, KeePassXC passkeys) is never shown or edited, only preserved.
- PIN unlock is Vaultline's own (not Windows Hello). A PIN lock drops the parsed database but keeps the credentials in memory; 3 wrong tries or a restart means a full lock.
- The CLI never reads or sets secret values (passwords, card numbers/codes/expiry, notes, OTP secrets, custom field values). `cli_server.entry_meta` is the only place entries are serialised for it; `compare` (finding duplicates) answers same/different per field, never a value. Card fixes run inside the app and report without values. It also refuses `{REF:...}` in anything it writes, because references are resolved when read.
- The one exception is `secret` (agent_access.py): off by default, only for entries in the one folder the user shares (by UUID, subfolders included; no cards or reference fields), only while fully unlocked, and every request is approved in a prompt where Deny is the default. The prompt can grant a pass (this entry for 15 min, or the whole shared folder for the time set in Settings: 15 min by default, 1 hour, until locked, or not offered); each read under a pass is still checked and logged. Any lock, a settings change or the tray's Stop agent access clears allowances. The access log never holds values. The CLI can't move entries or folders into the shared folder.
- The other exception is `profile add` (owner's decision, 2026-11-27): the CLI may send a sign-up profile's `identity_*` values (never passwords, cards or other fields), and it's saved only if the user presses Add in a prompt showing every value (Cancel is the default; 120 s without an answer, a lock or the caller going away cancels it). One prompt at a time, no `{REF:...}`, not straight into the shared folder, logged without values. The values come from a file or stdin, never command-line arguments.
- Auto-Type (`autotype.py`, `sendkeys.py`, `ui/autotype_flow.py`): the kdbx's Auto-Type settings (entry flag, sequence, window associations, folders' EnableAutoType/DefaultAutoTypeSequence) are read only, never written. Matching order: associations (KeePass wildcards), entry title, URL site name; the browser's name is taken off the window title for the last two. Only a single association match types without the picker (page titles can be set by any website). Typing only while fully unlocked, into the window remembered when asked, checked before every keystroke; never into Vaultline's own windows, and refused for higher-integrity (admin) windows. Typed values are never logged or put in messages. `sendkeys.focused_box` reads only the focused box's kind (IsPassword, control type, process) via UI Automation, never its value; a whole-login fill in a password box types `{PASSWORD}{ENTER}`, and "can't tell" falls back to the whole login. Window titles are shown as plain text, never as HTML.
- Cards use the field names KeePassXC creates when importing from Bitwarden: `card_number` and `card_code` (protected), `card_expMonth`, `card_expYear`, `card_cardholderName`, `card_brand`, plus `Phone` and `Phone (local)`. The website is the normal URL field. Older layouts are still read.
- Sign-up profiles (`identity.py`): ordinary entries with `identity_*` custom fields, Bitwarden's names with KeePassXC's prefix (`identity_firstName`, `identity_lastName`, `identity_email`, `identity_phone`, `identity_birthDate` as YYYY-MM-DD and the only protected one, `identity_address1`, `identity_city`, `identity_state`, `identity_postalCode`, `identity_country`). KeePassXC's joined `identity_name`/`identity_address` are read and split in the form, for the user to check. Profiles are never typed as a whole login, matched for Auto-Type or handed to agents. Fill format menus send a token (`identity_birthDate:mdy`); the value is looked up only on the typing side, on one line.
- New login for this window (`AutoTypeFlow.new_login`): saved through the normal save first; typing starts only after `applied` says it worked, and a lock in between drops it. It then walks the form from the focused box: a text box gets the profile value its label (UIA Name, never Value) asks for (`identity.field_for_label`), a standard drop-down labelled Month/Day/Year/Gender/Province/Country gets its value typed (the birth date only goes there); custom drop-downs that ignore typing are left to the user, unknown boxes are skipped with Tab, the password goes only into a box UIA reports as a password box (and the next one if it's also one), it stops after the password or 30 boxes, and never presses Enter. Browsers need time: wait before the first question, ask again if the first says "can't tell", pause after each Tab. The website comes from the browser's address bar (`sendkeys.browser_address`: the window's first text box, only if it's named like an address bar; asked for on 2026-11-27), trimmed by `autotype.site_url` to scheme://host[:port], never the path or query; not from the window title (pages set that). This is the only UIA Value read, and never from a page. Sign-up words in the title only reorder the button.
- The entry form opens inside the main window (a stack page, like Settings) with its own title-bar pin, not as a separate window.
- The window draws its own title bar (`ui/frameless.py`, `ui/titlebar.py`): Windows keeps the caption/thick-frame styles and is told what each pixel is through WM_NCHITTEST, so snapping, resizing and the snap-layout flyout stay native. Don't change Qt window flags at runtime (that resets those styles); "keep on top" uses SetWindowPos. A window narrower than 720px is the compact view.
- Tests use private pipe names (`VAULTLINE_INSTANCE`, set in tests/conftest.py) so they can never talk to a running Vaultline.
- Tests and the demo vault use made-up data only.
